# UrBackup Linux snapshot-hook integration

## Status

This is the first real integration layer between UrBackup's existing Linux image-backup snapshot interface and Proxmox VE/ZFS.

It deliberately does **not** patch UrBackup's network protocol or `ImageThread`. Upstream UrBackup already supports external Linux volume snapshot scripts through `snapshot.cfg`.

## Upstream contract

For Linux image backups, UrBackup executes a configured `create_volume_snapshot` helper. The helper must print a line beginning with:

```text
SNAPSHOT=<readable snapshot block-device path>
```

UrBackup then uses that path as the image source. When the image job is released, it calls `remove_volume_snapshot`.

## Included files

- `integration/urbackup/pve_volume_snapshot.py` — lifecycle/state manager
- `integration/urbackup/create_volume_snapshot` — UrBackup-compatible create wrapper
- `integration/urbackup/remove_volume_snapshot` — UrBackup-compatible remove wrapper
- `integration/urbackup/snapshot.cfg.example` — configuration snippet

Every generated code/configuration file carries an explicit notice that it was generated by ChatGPT and has not been reviewed by a human software developer.

## V1 behavior

For an image request whose original target is a Proxmox VM ZVOL such as:

```text
/dev/zvol/rpool/data/vm-150-disk-1
```

the hook:

1. extracts VMID 150 from the ZVOL name,
2. enumerates all ZFS-backed VM payload volumes through `qm config` and `pvesm path`,
3. records the existing `snapdev` value and property source for every VM ZVOL,
4. creates one Proxmox-managed VM snapshot using `qm snapshot`,
5. therefore lets Proxmox/QEMU Guest Agent coordinate freeze/thaw,
6. temporarily sets `snapdev=visible` on the relevant datasets,
7. returns the requested read-only snapshot ZVOL path as `SNAPSHOT=...`,
8. keeps state under `/run/urbackup-proxmox-agent`,
9. on UrBackup release, restores the original `snapdev` semantics and deletes the Proxmox snapshot.

## Important V1 limitation

The first end-to-end UrBackup test should use **only the primary VM disk (`scsi0`) as the UrBackup image source**.

Proxmox still snapshots scsi0, EFI and TPM together, preserving a consistent VM state. However, UrBackup's multi-image scheduling/grouping semantics still need validation before we expose EFI and TPM as separate UrBackup image jobs sharing a single lifecycle.

Do not yet use this integration for production backups.
